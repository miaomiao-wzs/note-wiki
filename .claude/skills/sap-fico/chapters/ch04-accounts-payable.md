# Chapter 4: 应付模块

## Core Idea
应付模块处理企业与供应商之间的债务业务，结构与应收模块高度对称，核心是供应商主数据的三视图和与MM采购模块的集成。

## Frameworks Introduced
- **供应商三视图结构**: 供应商主数据分为基本视图（client层）、公司代码视图（财务属性）、采购视图（采购属性）。
  - When to use: 创建和维护供应商主数据
  - How: FK01仅创建基本+公司代码视图（财务专用供应商），MK01创建基本+采购视图，XK01创建全部三个视图

## Key Concepts
- **供应商（广义）**: 包括常规供应商和所有对企业有债务关系的单位（如供电局、自来水公司等挂账单位）
- **统驭科目**: 供应商记账时自动记入的总账科目，统驭对象为K（供应商）
- **贸易伙伴**: 集团内成员单位的供应商，填写对应"公司"编码，为合并抵销服务
- **账户组**: 决定供应商编号方式、编号范围、是否一次性供应商、字段状态
- **付款条件**: 决定应付款的到期日计算规则
- **现金管理组**: 用于现金预测，将未来现金流出按用途分组

## Mental Models
- Use "供应商≠仅是卖方" when defining vendor scope — SAP中供应商是广义的，包括所有对企业有债务关系的单位
- Think of 应付与应收 as "镜像结构" — 两个模块的主数据结构、组织结构、统驭科目机制完全对称
- Use "集团内供应商单独设账户组" to enforce 合并要求 — 编码建议用"前缀+公司编码"，与集团内客户保持一致

## Anti-patterns
- **搜索项留空**: 标准报表（如供应商余额报表）只显示编码和搜索项，缺失会导致报表不可读
- **忽略对冲配置**: 仅在控制视图设置客户编号不够，还需在公司代码视图的支付交易中勾选"结算客户"
- **采购组织与公司代码关系不清**: 采购组织可属于某公司代码（自动带出公司代码），也可是"万能的"采购组织（需手工输入公司代码）

## Key Takeaways
1. 供应商是广义概念，涵盖所有有债务关系的单位
2. 应付模块与应收模块结构高度对称，学习时可对照理解
3. 集团内供应商必须设置贸易伙伴，编码规则与集团内客户保持一致
4. 采购组织与公司代码的对应关系决定了采购订单中公司代码是否自动带出
5. 对冲功能需要客户和供应商双方主数据都做相应设置
