# Chapter 10: 合并模块

## Core Idea
合并模块（EC-CS）处理集团内多家公司代码之间的合并与抵销，核心是合并单元的组织结构、合并组层次结构和数据收集方式。

## Frameworks Introduced
- **合并单元-合并组层次结构**: 合并单元（Consolidation Unit）是合并的基本单位，按股权投资结构排列成树形层次结构，每个节点称为合并组（Consolidation Group）。
  - When to use: 设计集团合并的组织架构
  - How: 通过CX1X维护合并组层次结构

- **数据收集方式**: 合并单元的数据如何传递到合并集团——从FI实时更新、灵活上载等方式。
  - When to use: 配置合并数据的传递机制
  - How: "从FI实时更新"意味着每张FI凭证生成时，合并凭证同时生成

## Key Concepts
- **合并单元（Consolidation Unit）**: 合并的基本单位，通常对应公司或公司代码
- **合并组（Consolidation Group）**: 合并层次结构中的节点，也称"合并集团公司"
- **合并集团（Consolidation Group）**: 合并的顶层组织
- **集团科目表**: 合并层面使用的科目表，与操作科目表建立对应关系
- **组科目号**: 操作科目表中每个科目对应的集团科目
- **贸易伙伴**: 标识内部交易的对方公司，为合并抵销提供依据

## Mental Models
- Use "公司=合并单元" as default mapping — 在多数情况下，公司、公司代码、合并单元是1:1:1的关系
- Think of 合并 as "消除内部交易" — 通过贸易伙伴字段识别内部交易，通过合并抵销消除集团内往来
- Use "集团科目表早期规划" to prepare for consolidation — 应收应付要区分关联方和非关联方

## Anti-patterns
- **忽略集团科目表规划**: 项目早期不规划集团科目表，后期合并时需要大规模调整科目结构
- **贸易伙伴未设置**: 集团内客户/供应商不设贸易伙伴，合并抵销缺乏数据基础
- **合并单元与公司代码关系不清**: 应明确每个合并单元对应哪些公司代码

## Key Takeaways
1. 合并的基本单位是合并单元，通常对应公司或公司代码
2. 合并组层次结构按股权投资关系排列
3. 数据收集方式决定了合并数据的传递时机和方式
4. 集团科目表和贸易伙伴是合并的数据基础，应在项目早期规划
5. 合并抵销的核心是通过贸易伙伴识别并消除内部交易
