# Chapter 6: 成本中心会计模块

## Core Idea
成本中心会计（CO-CCA）是CO模块的基础，以控制范围为组织结构，通过成本中心归集和输送费用，连接FI与CO模块。

## Frameworks Introduced
- **控制范围-公司代码关系**: 控制范围是企业内部管理成本费用的组织，与公司代码是一对多关系。
  - When to use: 设计CO模块的组织架构
  - How: 通过OX19将公司代码分配给控制范围；控制范围的科目表和会计年度变式必须与下属公司代码一致

- **成本中心费用流转模型**: 成本中心是费用归集的纽带——一方面归集各类费用，另一方面输送到工单（制造费用）或CO-PA（销售/管理费用）。
  - When to use: 理解成本中心在企业成本管理中的定位
  - How: 费用通过FI记账归集到成本中心，月末通过分配/分摊/作业价格重估输送到工单或CO-PA

## Key Concepts
- **控制范围（Controlling Area）**: CO模块的组织结构，可包含多个公司代码，用于内部管理会计
- **成本中心（Cost Center）**: 费用归集和输送的基本单位
- **成本中心标准层次**: 控制范围下所有成本中心的权威树形结构
- **版本（Version）**: 计划和实际数据的管理，版本0为SAP标准配置（同时编制计划和实际数据）
- **作业类型（Activity Type）**: 成本中心提供的服务计量单位，用于将费用输送到工单
- **初级成本要素**: 来自总账科目的成本要素，FI记账时自动产生CO凭证
- **次级成本要素**: 仅在CO内部使用的成本要素，用于内部分配和分摊

## Mental Models
- Use "控制范围=管理会计的边界" when designing CO架构 — 同一控制范围下必须使用相同的科目表和会计年度变式
- Think of 成本中心 as "费用中转站" — 归集费用是入口，输送费用到工单/CO-PA是出口
- Use "货币类型决定多币种策略" — 货币类型30（集团公司货币）适用于国际化企业

## Anti-patterns
- **控制范围与公司代码不一致**: 同一控制范围下的公司代码必须使用相同的科目表和会计年度变式
- **忽略版本管理**: 应区分计划版本（年初预算、滚动预算等）和实际数据版本
- **CO公司代码确认未勾选**: 国内企业一般应勾选，防止跨公司代码过账

## Key Takeaways
1. 控制范围是CO模块的组织基础，与公司代码是一对多关系
2. 成本中心是费用归集和输送的纽带，连接FI与CO
3. 版本管理区分计划和实际数据，支持多版本对比分析
4. 控制范围的货币和科目表必须与下属公司代码保持一致
5. 成本中心通过作业类型将制造费用输送到工单，通过分配/分摊将销售管理费用输送到CO-PA
