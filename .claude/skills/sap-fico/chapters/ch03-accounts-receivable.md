# Chapter 3: 应收模块

## Core Idea
应收模块处理企业与客户之间的债权业务，核心是客户主数据的三视图结构（基本视图、公司代码视图、销售视图）和与SD模块的集成。

## Frameworks Introduced
- **客户三视图结构**: 客户主数据分为基本视图（client层通用信息）、公司代码视图（财务属性）、销售视图（销售属性）三个层次。
  - When to use: 创建和维护客户主数据
  - How: FD01仅创建基本+公司代码视图（财务专用客户），VD01创建基本+销售视图，XD01创建全部三个视图

- **账户组控制机制**: 账户组决定客户的编号方式、编号范围、是否一次性客户、字段状态（可选/必输/隐藏）。
  - When to use: 设计客户编码规则、控制主数据字段的显示逻辑
  - How: 在后台配置账户组，前台创建客户时选择

## Key Concepts
- **统驭科目**: 客户记账时自动记入的总账科目，统驭对象为D（客户）
- **贸易伙伴（Trading Partner）**: 当客户是集团内成员单位时，填写对应的"公司"编码，为合并抵销提供依据
- **总部/分支机构**: 总部客户编号填入分支机构的"总部"字段，系统自动将应收款归入总部名下
- **付款条件**: 决定到期日计算的收付基准日、账期天数和折扣
- **销售范围（Sales Area）**: 销售组织+分销渠道+产品的组合，与公司代码是多对一关系
- **对冲功能**: 同一单位既是客户又是供应商时，通过主数据互相关联实现债权债务对冲

## Mental Models
- Use "客户≠仅是买方" when defining customer scope — SAP中客户是广义的，包括所有对企业有债务关系的单位或个人（如押金供应商、借款员工）
- Think of 三视图 as "分权管理" — 基本视图由基础数据团队维护，公司代码视图由财务维护，销售视图由销售维护
- Use "集团内客户单独设账户组" to enforce 合并要求 — 将贸易伙伴设为必输，编码用"前缀+公司编码"

## Anti-patterns
- **搜索项留空**: 某些标准报表（如客户余额报表）只显示编码和搜索项，不显示名称，搜索项缺失会导致报表难以识别
- **忽略贸易伙伴设置**: 集团内客户如果不设贸易伙伴，未来合并抵销将缺乏数据基础
- **对冲功能配置不完整**: 仅在常规视图设置供应商编号不够，还需在公司代码视图勾选"具有供应商的清算"

## Key Takeaways
1. 客户是广义概念，涵盖所有有债务关系的单位或个人
2. 账户组是客户管理的核心配置，决定编号方式和字段状态
3. 集团内客户必须设置贸易伙伴，为合并抵销做准备
4. 同一单位既是客户又是供应商时，需在双方主数据互相关联并勾选对冲标识
5. 搜索项必须正确设置，否则影响报表阅读
