# Chapter 1: SAP基础知识

## Core Idea
SAP系统的入门基础：理解Client/服务器架构、前台操作界面、后台配置体系，以及SAP菜单、事务代码、收藏夹等核心操作概念。

## Frameworks Introduced
- **三层架构（服务器-Client-用户）**: SAP环境由服务器→Client→用户三级构成。一个服务器可包含多个Client，每个Client是一套独立的业务数据环境。
  - When to use: 理解SAP系统环境划分、数据隔离、系统管理
  - How: 开发机(DEV)→验证机(QAS)→生产机(PRD)，配置在DEV中进行，通过传输请求逐级传递

- **前台-后台分离**: SAP将业务操作（前台）与系统配置（后台/IMG）严格分离。前台是用户日常操作界面，后台是顾问配置系统行为的地方。
  - When to use: 区分"谁做什么"——用户操作前台，顾问配置后台
  - How: 前台通过SAP菜单或事务代码进入；后台通过SPRO进入IMG配置

## Key Concepts
- **Client（客户端）**: 登录到哪一套数据环境，是SAP数据隔离的最高层级
- **事务代码（Transaction Code）**: 进入具体操作界面的快捷方式，如FB50、FAGLB03
- **收藏夹（Favorites）**: 用户可将常用事务添加到收藏夹，方便快速访问
- **OK_CODE框（命令框）**: 输入事务代码的区域，位于界面左上角
- **传输请求（Transport Request）**: 后台配置变更的载体，记录并传递配置变更到其他环境

## Mental Models
- Use "三层环境模型" when planning any system change — 先在DEV配置，测试通过后传到QAS验证，最后传到PRD生产
- Think of Client as "平行宇宙" — 同一服务器上多个Client共享程序和表结构，但业务数据互相隔离
- Use "前台走路径，后台走IMG" to understand SAP的两大操作体系 — 初学者应从菜单路径入手理解逻辑层次，而非直接记忆事务代码

## Anti-patterns
- **在生产环境做测试操作**: PRD环境不可直接更改配置或做测试，否则影响真实业务数据
- **直接背事务代码而不理解路径**: 初学者应通过菜单路径理解SAP的业务逻辑层次
- **忽略状态栏消息**: 红色=报错必须解决，黄色=报警可忽略但需关注业务规则，绿色=告知性信息

## Reference Tables

### SAP屏幕6大区域
| 区域 | 说明 |
|------|------|
| 菜单栏 | 业务操作指令，横向排列在顶层 |
| 系统功能栏 | 保存、退出、返回等通用功能按钮 |
| 标题栏 | 屏幕标题 |
| 应用工具栏 | 当前界面专有操作按钮 |
| 屏幕区域 | 用户完成操作的主要区域 |
| 状态栏 | 报错/报警/消息提示，右侧显示服务器和状态信息 |

## Key Takeaways
1. SAP环境分DEV→QAS→PRD三级，配置变更必须通过传输请求逐级传递
2. 前台操作用SAP菜单或事务代码，后台配置用SPRO进入IMG
3. 初学者应从菜单路径层层展开理解SAP的业务逻辑，而非死记事务代码
4. 状态栏是诊断问题的第一入口，双击报错信息可查看详细诊断和建议
5. 通过状态栏右侧确认当前操作的环境（系统ID、Client），避免在PRD做测试
