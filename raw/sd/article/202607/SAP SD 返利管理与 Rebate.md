## SAP SD 返利管理：年采购额500万返3个点——为什么财务说系统算的对不上？Rebate全链路拆解（系列第38篇）

> 销售总监签了大单："客户承诺年采购额 500 万，给 3% 返利。财务你帮我算清楚，年底一次结算。"
> 
> 财务月底一看 VBO2：系统显示应计返利 8 万，实际开的贷项凭证只有 6 万。"差了两万去哪了？"
> 
> 这就是 SAP SD 返利管理最经典的问题—— **应计（Accrual）和结算（Settlement）对不上** 。今天把这块硬骨头啃下来。

按照汽车零部件行业惯例，OEM 客户签的年度框架协议里几乎没有不带返利的。返利金额动辄几十万上百万，对不上就是财务事故。SAP 的 Rebate 标准功能只要配对了，比 Excel 算得准一万倍——但前提是 **你真的配对了** 。

---

## 一、返利是什么？为什么要有 Accrual？

### 1.1 返利的业务本质

```
返利 = 客户采购量大 → 供应商"返"一部分钱回去

典型返利协议：
  年采购额 ≥ 100万 → 返 1%
  年采购额 ≥ 300万 → 返 2%
  年采购额 ≥ 500万 → 返 3%

每季度/半年/年度结算一次
结算方式：开贷项凭证(贷记)抵扣应收账款，或直接打款
```

### 1.2 Accrual 是什么？为什么不能等到年底一次性算？

```
财务准则：权责发生制

1月卖50万给客户 → 预计年底要返1.5万（按3%预估）
  → 虽然现在不用付，但利润要扣掉这1.5万
  → 记"应计返利"（Accrual）：预计负债

每月都在做 Accrual → 利润表每月都被返利"吃掉"一部分
年底实际结算 → 多退少补 → 冲 Accrual
```

**Accrual 是为了让每月的利润表真实反映业务成本。**

### 1.3 为什么 Accrual 和 Settlement 对不上？

最常见的五个坑：

```
坑1：价格保护中的订单没计入 Accrual
  → 销售订单创建时未确认，发票没生成 → Accrual 不触发

坑2：退货/冲销发票 Accrual 未反向
  → 客户退了货，发票冲销了，但 Accrual 还在

坑3：部分结算的 Scale 跳档
  → 系统按当前累计额预估 scale，实际年底达到更高档

坑4：排除条件未生效（Manual Accrual Override）
  → 这张SO不应计提返利，但手动没改

坑5：返利结算日期范围错误
  → 结算时日期选错了，漏了或重复了某个期间的发票
```

## 二、SAP Rebate 标准配置全链路

### 2.1 三步走：协议→Accrual→结算

```
Step 1: 创建返利协议（VBO1）
  ├── 确定客户 + 返利条件类型
  ├── 确定有效期（年度/季度）
  ├── 确定 Scale 阶梯（采购额 × 返利率）
  └── 确定结算日历（每月一次/季度一次）

Step 2: 自动应计（Accrual）
  ├── 每次开票时系统自动计算 Accrual
  ├── Accrual = 发票金额 × 对应阶梯度返利率
  └── 过账到 FI：借 返利费用 | 贷 返利预提

Step 3: 结算（VBO2）
  ├── 到结算日期 → 运行 VBO2
  ├── 系统汇总有效发票总额 → 确定最终 Scale 档
  ├── 生成贷项凭证请求 → 自动生成 FI 凭证
  └── 冲 Accrual：借 返利预提 | 贷 客户应收账款
```

### 2.2 核心配置 Tcode 速查

| Tcode | 功能 | 说明 |
| --- | --- | --- |
| **VBO1** | 创建返利协议 | 核心入口，绑定客户+条件 |
| **VBO2** | 修改/结算返利协议 | 修改协议 + 执行最终结算 |
| **VBO3** | 显示返利协议 | 只读模式 |
| **VBO4** | 返利结算清单 | 查看结算历史和状态 |
| **VBO5** | 批量创建返利协议 | 按客户群批量创建 |
| **VBOF** | 更新返利协议 | 更新已结算的协议状态 |
| V/06 | 定义条件类型（Cond.Type） | B001~B009 等 |
| V/07 | 定义Access Sequence | 返利条件的存取顺序 |
| V/08 | 定义条件表（Cond.Table） | 销售组织+客户+物料 |
| V/15 | 定义返利协议类型 | 年度/季度/一次性 |
| V/25 | 定义返利结算的计价过程 | Check 条件计算顺序 |

### 2.3 关键条件类型

```
B001: 物料返利（按物料）
B002: 物料组返利（按物料组）
B003: 客户/物料返利
B004: 客户/物料组返利
B005: 客户/层级返利
B011: 销售组织返利
B018: 客户返利（按客户整体采购额，最常用）
```

## 三、Accrual 的核心机制——四张表

### 3.1 返利四张核心表

```
S060: 返利应计汇总表（按客户+条件汇总）
S136: 返利应计明细（按开票凭证行项目）
VBOX: 返利协议单据表（协议本身）
KONA: 返利协议条件记录表（条件数据）
```

### 3.2 Accrual 实时更新流程

```
VF01 创建发票
  ↓
系统检查：该客户是否有有效返利协议？
  ↓ 有
系统计算：发票金额 × 当前 Scale 返利率 = Accrual 金额
  ↓
更新 S136（写入应计记录）
  ↓
更新 S060（汇总到客户层级）
  ↓
FI 过账：借 返利费用/贷 返利预提
```

### 3.3 怎么看 Accrual 对不对？

```
-- 检查某客户的应计汇总
SELECT KUNNR,        -- 客户编号
       BONEM,        -- 条件记录号
       VKORG,        -- 销售组织
       SPART,        -- 产品组
       RWAKT,        -- 本次开票金额
       ZZBTR_ACTUAL, -- 实际 Accrual 金额
       ZZBTR_FINAL   -- 最终结算金额
FROM S060
WHERE KUNNR ='客户编码';

-- 与 VBOX 协议对比
SELECT BONEM,        -- 协议号
       KUNNR,        -- 客户
       BOSTA,        -- 状态（A=活动/C=已结算）
       AEDAT,        -- 创建日期
       KPEIN,        -- 条件定价单位
       KMEIN         -- 条件单位
FROM VBOX
WHERE KUNNR ='客户编码';
```

## 四、结算的 Scale 陷阱：跨档位差额

### 4.1 Scale 是怎么跳档的？

```
返利协议 Scale：
  0 ~ 200万 → 返 1%
  200万 ~ 500万 → 返 2%
  500万+ → 返 3%

客户采购进度：
  Q1: 150万 → Accrual 按 1% = 1.5万  ← 系统以为全年就这档
  Q2: 累计 350万 → 进入 2% 档
    → Q2新开发票按 2% Accrual = 4万
    → Q1 的 150万还需补 Accrual: 150万 × (2%-1%) = 1.5万
    → 这 1.5万叫 Retroactive Accrual（追溯应计）
```

**这就是坑3的来源——每月累积价的变化会让 Accrual 和预期对不上。**

### 4.2 SAP 的自动 Scale 处理

```
SAP VBO2 结算时自动：
  1. 汇总结算期间内所有有效发票
  2. 确定最终 Scale 档位
  3. 计算总返利 = ∑(每档金额 × 该档返利率)
  4. 扣除已 Accrual 金额 = 差额
  5. 差额生成贷项凭证（可能正可能负）

结算公式：
  Settlement = Total_Rebate_Earned - Total_Accrual_Accrued
```

## 五、汽车零部件的返利实战

### 5.1 OEM 年度返利（最常见）

```
客户：大众、宝马、奔驰等主机厂
典型协议：
  ├── 年度采购额 ≥ 500万 → 3%
  ├── 年度采购额 ≥ 1000万 → 3.5%
  ├── 年度采购额 ≥ 2000万 → 4%
  ├── 结算方式：季度预结算 + 年度终结算
  └── 结算方式：贷项凭证抵扣应收账款

SAP 配置要点：
  ├── 返利协议类型：按年度（BOTA=年度协议）
  ├── Accrual：每次开票自动计提
  ├── 结算日历：每季度一次 Partial Settlement
  ├── 年度 Final Settlement：全年汇总，多退少补
  └── 注意：退货和信贷凭证排除（避免 Accrual 虚高）
```

### 5.2 新机型推广激励（一次性返利）

```
场景：主机厂推广新车型 → 前三个月采购新型号传感器额外返 2%

SAP处理：
  ├── 协议类型：按物料 + 限定日期范围
  ├── 条件类型：B001（物料级返利）
  ├── 有效期：2026.07.01 ~ 2026.09.30
  └── 结算：10月一次性结算
```

### 5.3 高周转返利（物流驱动）

```
场景：客户自己来拉货 → 降低供应商物流成本 → 返 0.5%

SAP处理：
  ├── 通过订单类型/运达方区分
  ├── 或在 VOFM 中写 Formula 判断
  └── 独立的条件类型（ZREB）
```

## 六、返利管理的常见故障与修复

### 6.1 Accrual 丢失

```
症状：发票已开，但 S060/S136 中没有 Accrual 记录

排查：
  1. OB40：确认返利科目确定配置（TE码 BON）
  2. VBO3：确认协议有效期覆盖发票日期
  3. V/06：确认条件类型"应计"标记已勾选（KOAER）
  4. 检查 OVBN：定价过程中的条件类型是否包含返利条件

修复：
  → 如果是配置问题：补充配置后，VFx可重新计算
  → 如果发票已过账：用 TAC Z_REBATE_RECALC 重新计算（需开发）
```

### 6.2 Accrual 虚高（未排除退货）

```
症状：客户退货后 Accrual 没反向

原因：
  S060/S136 在退货开票时没生成负 Accrual 记录

配置检查：
  → V/06：条件类型的 "Reverse Accruals" 标记
  → 确认返利协议中退货相关发票类型是否覆盖

手动修复：
  → VBO2 输入协议号 → Extras → Manual Accrual → 输入负 Accrual
```

### 6.3 部分结算后协议状态卡死

```
症状：VBO2 点 Final Settlement 报错 "协议状态不允许最终结算"

原因：前一次 Partial Settlement 的贷项凭证还在批准中(blocked)

修复：
  1. VF02 → 找到上次结算生成的贷项凭证
  2. Release to Accounting
  3. VBO2 → 再次尝试 Final Settlement
```

## 七、一句话总结

> **SD返利管理 = 返利协议(VBO1) + 自动Accrual(每次开票) + 定期结算(VBO2)，核心在于 Accrual 和 Settlement 的对账。90%的"对不上"都是 Accrual 没考虑退货/信贷/Scale跳档。**
