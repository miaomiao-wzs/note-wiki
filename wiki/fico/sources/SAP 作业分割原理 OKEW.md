# SAP 作业分割原理 OKEW

## 来源信息

- 原始资料：`raw/fico/article/202607/SAP 作业分割原理 OKEW.md`
- 作者：Slashout
- 发布日期：2014-08-28
- 原文链接：[SAP 作业分割原理 OKEW](https://www.cnblogs.com/SlashOut/articles/3941093.html)

## 一句话结论

作业分割用于把成本中心归集的共同成本，按照不同作业类型的实际数量拆分；当作业类型的计量单位不一致时，可以借助权数指标把数量换算成统一的等效数量，再按等效数量比例分割成本。文章将 `OKES` 描述为定义分割结构，将 `OKEW` 描述为把结构分配到成本中心并定义分割规则。

## 文章要点

### 1. OKES 与 OKEW 的分工

按文章描述：

- `OKES`：定义分割结构，设置作业发送成本要素组、作业组等范围。
- `OKEW`：把分割结构分配到成本中心，并定义分割规则。
- 分割方法选择 `12`，并勾选 `Wt.`（权数指标）。

以上是剪藏中的配置描述，不代表所有 SAP 版本和企业系统的固定配置。`OKES`、`OKEW` 的具体事务码、字段含义、方法 `12` 与 `Wt.` 的系统行为，需在目标系统或相应版本官方文档中核验。

### 2. 为什么需要权重

文章示例混合了人天和小时两种作业单位：`22 人天`不能直接和`32 小时`相加。权重的作用，是把不同单位转换为同一套等效数量后再计算分割比例。

在示例中，`TFZY1:TFZY2 = 8:1` 可理解为文章采用“1 人天约等于 8 小时”的换算规则：

```text
TFZY1 等效数量 = 22 人天 × 8 = 176
TFZY2 等效数量 = 32 小时 × 1 = 32
总等效数量 = 176 + 32 = 208
```

这表示业务量换算权重，不应直接等同于作业价格比例。实际权重应由企业对作业量、计量单位和管理口径的定义决定。

## 示例计算

场景：成本中心 A 归集咨询费 `120,000 CNY`，需要按两个作业类型分割：

- `TFZY1`：初级顾问，按人天计量，发生 `22 Days`；
- `TFZY2`：资深顾问，按小时计量，发生 `32 Hrs`。

### 不使用权重

若不启用权重，文章的计算意图是直接按数量比例分割：

```text
总数量 = 22 + 32 = 54

TFZY1 = 120,000 ÷ 54 × 22 ≈ 48,889 CNY
TFZY2 = 120,000 ÷ 54 × 32 ≈ 71,111 CNY
```

原文第二个公式写成了 `× 36`，与前文的 `32 小时`不一致；本页按上下文将其判断为疑似笔误，不把 `36` 作为有效业务数据。

但从业务建模角度看，直接相加人天和小时并不严谨，因为两者的计量单位不同；这正是文章引入权数指标的原因。

### 使用权重

采用 `TFZY1:TFZY2 = 8:1`：

```text
TFZY1 等效数量 = 22 × 8 = 176
TFZY2 等效数量 = 32 × 1 = 32
总等效数量 = 176 + 32 = 208

TFZY1 = 120,000 ÷ 208 × 176 ≈ 101,538 CNY
TFZY2 = 120,000 ÷ 208 × 32 ≈ 18,462 CNY
```

两项结果合计约为 `120,000 CNY`。文章中的 `3,000 元/人天`、`6,400 元/人天`和 `800 元/小时`是示例背景；不能仅凭该示例推导企业系统的标准价格或权重配置。

## 与相关 CO 处理的边界

- **作业分割**：解决成本中心内部共同成本如何在多个作业类型之间拆分。
- **实际作业分配/确认**：记录作业提供方和接收方之间的实际作业数量及金额关系。
- **成本中心分配/分摊**：把发送方成本中心的成本转移给接收方成本中心；`KSV`/`KSU` 循环不应与 `OKES`/`OKEW` 规则机械等同。
- **作业价格计算**：根据成本中心成本和作业数量计算或维护单位价格，实际执行方式要结合系统版本和月结方案确认。

文章提到的 `KSS2`、`KSII` 关联以及“最后 allocation 数据过账到 `COKL`”的说法，当前仅作为来源线索保留，尚未通过目标 SAP 系统或官方资料验证。

## 生产配置维护边界

本文只整理作业分割来源文章的原理和待核验事项，不把生产客户端临时开放写成 SAP 标准步骤。用户补充的现场方法是：若生产客户端设置为“**不允许更改**”而无法编辑 `OKEW`，经授权、审批、备份和回退准备后，通过 `SCC4` 临时改为“**不带自动记录的更改**”，完成必要修改和验证后立即恢复为“**不允许更改**”。

“不带自动记录的更改”可能影响正常传输和审计追踪；具体选项行为、适用版本和企业变更要求应在目标系统确认。完整流程见 [[wiki/fico/synthesis/生产环境 OKB9 OKEW 临时维护方法]]。

## 待确认事项

1. `OKES`、`OKEW` 在目标 SAP 版本中的事务码、配置对象和字段定义。
2. 分割方法 `12` 的准确系统含义，以及 `Wt.` 是否表示权数指标、如何参与作业数量换算。
3. 权重应由作业单位换算、业务产能还是企业计价口径确定；不能直接照搬文章的 `8:1`。
4. `KSS2` 与作业分割的具体执行关系，以及是否必须在 `KSII` 前后执行。
5. `COKL` 是否为该场景实际结果数据表，需用系统查询或官方数据字典确认。
6. 原文示例的标准价格、金额和实际数量仅用于解释计算，不能作为企业配置结论。
