# SD Rebate

## 来源信息
- 来源类型：article / Markdown 剪藏
- 原始位置：`raw/sd/article/202607/SAP SD 返利管理与 Rebate.md`
- 外部来源：[微信公众号原文](https://mp.weixin.qq.com/s/03CGzlPtVd0cKmCOiHQg8A)

- 适用模块：SD / FI

## 一句话结论
SD Rebate 的核心是返利协议、开票时应计和按期间结算三者闭环；对账差异通常要同时检查协议有效期、条件技术、退货/贷项冲销、阶梯 Scale、部分结算和结算日期范围。

## 关键内容

### 1. 业务链
典型链路为：

`VBO1 创建协议 → 开票时自动 Accrual → VBO2 部分/最终结算 → 生成贷项凭证并冲销应计`

返利的应计用于按权责发生制反映预计返利负债，最终结算根据有效销售和协议条件进行多退少补。实际借贷科目、结算凭证类型和审批状态取决于企业配置。

### 2. 配置入口
原文列举：`VBO1`、`VBO2`、`VBO3`、`VBO4`、`VBO5`、`VBOF`，以及 `V/06`、`V/07`、`V/08`、`V/15`、`V/25`。这些事务码可作为排查入口，但条件类型、协议类型、计价过程和应计过账配置应以当前系统为准。

原文示例中的 `B001`–`B005`、`B011`、`B018`、`BOTA` 等条件或协议标识属于文章案例，不应在未核验系统配置前直接套用。

### 3. 阶梯和追溯应计
当累计采购额跨越 Scale 档位时，前期销售可能需要补提差额，形成 Retroactive Accrual。最终结算至少应核对：有效发票范围、退货和贷项、每档适用金额、已计提金额及结算期间。

### 4. 资料中的数据对象
原文提到 `S060`、`S136`、`VBOX` 和 `KONA`。查询这些对象前应确认系统版本、激活的返利方案、表结构和授权；原文 SQL 中的“客户编码”是占位示例，不是真实企业数据。

### 5. 常见差异排查
- 发票已开但没有应计：检查协议有效期、条件类型应计标记、定价过程和科目确定。
- 应计偏高：检查退货/贷项是否反向、排除条件和手工应计。
- 结算金额差异：检查 Scale 跳档、追溯应计、部分结算及日期范围。
- 最终结算受阻：检查上次结算生成的贷项凭证是否已释放并完成后续状态更新。

## 安全与适用边界
返利协议会影响客户结算和财务负债。生产系统中修改协议、手工应计或重算前，应确认审批、会计凭证状态、期间和审计追踪，并先在测试环境验证。
